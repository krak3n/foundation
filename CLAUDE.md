# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Working process

Work in approved steps: plan first (with numbered decisions and a recommendation for each), then tests only once the user says to go ahead, then implementation once they say so again. Never implement from a plan alone. Keep the public API thin, explicit over implicit, dependencies pointing child to parent, and docs and examples accurate.

## Documentation

`README.md` is the front door: short, plain, and checked by tests (`readme_test.go`, `quickstart_unix_test.go`) for what can go wrong without anyone noticing, not for how it is worded: the quick start program is byte for byte `examples/quickstart/main.go` (which is built and run as a real process: serves on loopback, stops on SIGINT, refuses a bad address, `--help`, `--dry-run`), every `foundation.X`/`f.X` it shows exists, its Go version is the one in `go.mod`, no example listens on every interface without saying so, every relative link and heading resolves, and `LICENSE` is the unmodified Apache-2.0 text (SHA-256 checked). Section order, length and wording are deliberately not tested, so the README can be edited freely. Change the example and the README together. The detail lives in `CONFIG.md`; `docs/CONCEPT.md` and `docs/FLAGS.md` are the original design notes, kept as history (the code and `CONFIG.md` are the reference).

## Security requirements

This framework should be as hard to attack as we can make it. **Every new feature is validated for a strong security posture before it counts as done**, not afterwards:

- **Plan:** every plan has a threat model: who controls each input (network, configuration, supply chain), what an attacker gains, and what the feature does about it.
- **Tests first:** hostile-input tests are written with the other tests, for example oversized, malformed, duplicate, ambiguous, control-character and symlink/FIFO inputs, plus a fuzz test for any parser. Each audit finding gets a regression test.
- **Defaults:** fail closed (a mistake stops startup, it never changes what the service is), be explicit rather than inferred, and bound every resource (size, time, goroutines, recursion).
- **No leaks:** no configuration value ever appears in an error or a log line (reasons only), text that an attacker can influence is escaped before it is logged (this includes the text of a `Fail` and of a recovered panic, and the `fn` name of a function, which are escaped and the text cut at 8 KiB with `safetext.Clip`; the stack of a panic is the runtime's and is logged as it is), and responses that anyone can reach carry only a verdict.
- **Dependencies:** the core has none. A provider that needs one is a separate module, with its advisory history and parser behaviour (duplicate keys, aliases, size) reviewed first.
- **Release pipeline:** the rules under "Release pipeline" below apply to every workflow change.
- **Record:** findings go in `SECURITY_AUDIT.md`, which is private and must never be committed; `SECURITY.md` is the public policy.

## Pull requests

Every change reaches `main` through a pull request. For an agent, in order of importance:

- **One purpose, small.** A pull request does one thing and can be read in one sitting. Split the work the way the history was: each commit builds and passes its own tests, and later commits build on earlier ones.
- **Conventional commits.** Every commit message and the pull request title is `type(scope)!: subject`: a type from `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `ci`, `build`, `chore`, `revert`, `style`; an optional scope from `internal`, `config`, `watch`, `interrupt`, `http`, `yaml`, `examples`, `deps`; a lowercase imperative subject with no full stop (Dependabot's `chore(deps): Bump ...` is the one exception); a header of at most 72 characters; a blank line, then a body that says why. Add `BREAKING CHANGE:` in the body for a change that breaks the API. release-please reads these to write the changelog and pick the version, and CI refuses a pull request that does not follow them (`.github/scripts/check_commits.py`; run `make check-commits` first). No merge commits in a branch: rebase onto `main`. End a commit made by an agent with the `Co-Authored-By` line the session gives.
- **Branch, never `main`.** Push a branch and open a pull request. Never push to `main`, never force-push a branch that someone else has looked at, never merge your own pull request, and never change repository settings or bypass a check (`--no-verify`, a skipped or loosened test). Fix the cause, or say it can't be fixed.
- **Adversarial review before every push.** Review the whole branch diff (`git diff origin/main...HEAD`) as someone who wants to find a fault, and prefer a reviewer that did not write it (a separate agent, or `/code-review`) that is told to look for problems and not to approve. Be nit-picking: correctness and edge cases; the threat model (is an input trusted that should not be, does an error or log carry a configuration value, is a resource unbounded); tests that would pass for the wrong reason (no assertion, checking their own output, a mock of the thing under test); a hostile-input or fuzz test for each new input; public API that did not need to be public; `CLAUDE.md`, the README, `CONFIG.md` and the examples drifting from the code; naming, comment density, dead code and formatting. Fix what it finds, or record why it was left. CI can't check that this happened, so the pull request says so.
- **The description is honest.** It follows `.github/PULL_REQUEST_TEMPLATE.md`: what, why, how it was verified (the commands and what they said, and anything skipped or not run), the security impact, and the result of the review (how many findings, which were fixed, which were left and why). Never claim a check passed that has not run.
- **Keep the docs true.** A change updates `CLAUDE.md` (including the CI table), the README, `CONFIG.md` and the examples in the same pull request, and its tests with it.
- **Nothing private.** Never commit `SECURITY_AUDIT.md`, never force-add (`git add -f`) a file that `.gitignore` leaves out, and never put a configuration value or a secret in a commit, a description or a log.

Merge with a merge commit or a rebase, not a squash, so each commit's message reaches release-please (a squash makes the title the only message, and the title is checked too).

### Release pipeline

Workflows are in `.github/workflows`. Rules, enforced by `.github/scripts/check_workflows.py` (run by `make lint-workflows` and CI, alongside `actionlint` and `zizmor`): every `uses:` is pinned to a full commit SHA with the version in a comment (Dependabot updates both), event data (`github.event.*`, branch/tag names, inputs) is never pasted into a `run:` script but passed through `env:`, each workflow has top-level `permissions:` with grants per job, every checkout sets `persist-credentials: false`, and every job has `timeout-minutes`. **The release App**: a pull request made with `GITHUB_TOKEN` starts no workflow, so `release-please.yml` and `release-cascade.yml` make a token with `actions/create-github-app-token` (for this repository only, `permission-contents` and `permission-pull-requests` only, revoked when the job ends) from the variable `RELEASE_CLIENT_ID` (the App's Client ID, which is public) and the secret `RELEASE_APP_PRIVATE_KEY` of the `Release` environment (the jobs say `environment: Release`). `check_workflows.py` refuses the key anywhere but that step's `private-key`, in a workflow that a pull request, comment, issue or fork can start (only push, release, workflow_dispatch and schedule may), any other secret (no personal token) and `secrets: inherit`, `skip-token-revoke`, a token for more than one repository or with other permissions, and a job that uses it outside `Release`. See `SECURITY.md` for setting it up. The release tag is written into `.release/versions.yaml` by `.github/scripts/set-core-version.sh`, which reads `TAG` from the environment and refuses anything that isn't a plain version (git allows `$`, backticks and quotes in tag names); its tests are `test-set-core-version.sh`. `release-cascade.yml` also has `workflow_dispatch` with a `tag` input so it can be rehearsed before a real release. **Go versions** (`ci.yml`): the tests run on `stable` and `oldstable` (`setup-go` aliases, `fail-fast: false`, `GOTOOLCHAIN=local` so the older release is never replaced by a newer toolchain); the `go` line of every `go.mod` is the release before the current stable one (the oldest tested), checked by the `go-version` job with `.github/scripts/check_go_versions.py` (text only, never runs a go.mod; no `toolchain` lines; expected version from `go env GOVERSION`, so it goes red when Go ships, also weekly by `schedule`, and `make go-version GO=1.xx` is the fix); `staticcheck`, `tooling`, `govulncheck` and the release workflows run on `stable`. `security.yml` runs `govulncheck` (also weekly) and `zizmor`. See `SECURITY.md` for the reporting policy and the repository settings that can't be checked in.

Releases are made by release-please (it creates the tags) and the cascade; there are no release targets in the Makefile. Module sets are defined in `.release/versions.yaml`.

## Architecture

### Core concept

Foundation is modelled after Go's `testing.T`. `foundation.Run` creates a root `*F` node; each `f.Run(name, fn)` creates a child node that executes `fn` in its own goroutine. Functions are **sequential by default** — the parent waits for each child before starting the next. Calling `f.Parallel()` releases the parent immediately while still tracking the child until it finishes.

The `*F` tree gives:
- **Upward failure propagation**: `f.Fail(err)` logs (the text of `err` escaped, so a newline is `\n`, and cut at 8 KiB), starts shutdown, then calls `runtime.Goexit()` on the current goroutine so cleanups still run. Every `Fail` (and every recovered panic, logged with a `stack` attribute) marks the run as failed, and once everything has stopped `Run` ends the process with exit status 1. `f.Shutdown(msg)` is not a failure: `Run` returns normally (exit 0, e.g. after SIGINT/SIGTERM).
- **Ordered shutdown**: shutdown stops live nodes in the reverse of the order they started, each finishing (or timing out) before the next is signalled. A node's context is only cancelled when its turn comes, so `f.Context().Done()` does not fire for every node at once (the root's does, immediately). For a node the order is: cancel its context, let its function return, stop its children in reverse start order, run its cleanups. If a node's function is blocked in a sequential child, that child is stopped first.
- **Probes and instances** (`probes.go`): the probes of an instance are the instance's, and there is no way to give the framework a registry (`WithRegistrar` was removed: nothing used it but tests, which read `f.Probes()`, and a registry that outlives an instance needs the framework to run the program's code on shutdown). `f.Probes()` makes a `*monitor.Registry` for the instance; when it has stopped completely (after `root.run`, so after every function and cleanup, and before the next instance starts: `endProbes`) the registry is cleared (`Registry.Clear`, which can't fail and is not part of `monitor.Registrar`) and the instance is sealed, whether or not it ever asked for probes: a sealed `Add` is ignored and `Seq` is empty, so an abandoned function can't reach anything of the instances after it. It is at the end, not when the function that added a probe stops, so a service that has stopped serving keeps failing its probe until it is gone (a missing probe passes). A program registers its probes from the root function, which runs again for each instance, and a candidate has a registry of its own so it can't clash with the live instance. `health.WithRegistry(r)` is the program's own registry for the health server alone: the framework only reads it and never clears it, so a program that restarts makes it in the root function.
- **Restart** (`restart.go`): `f.Restart(reason)` is like `f.Shutdown` but the whole program starts again: `Run` is a loop over instances, each a new root `F` (tree, context, stop sequence, probe registry; options are applied to it afresh) while the `process` (`failed`, `final`, the current instance) persists. Callable from any function or goroutine, never halts or waits. The old instance is stopped completely (usual order, cleanups) before the next starts, so two never overlap; a function abandoned by the timeout during a restart fails the run (exit 1) instead, and a new instance that fails or panics fails the run (no retry). **A real shutdown always wins**: `shutdown` (`Shutdown`, `Fail`, dry run complete) sets `process.final` before it looks up the current instance, and a new root is registered under the same lock that checks it, so a shutdown can't fall between two instances; it is honoured from an old instance's `f` too, and applies to the current one. `Restart` is ignored when final, already stopping (any number of requests while one is under way are one), from a replaced instance, or in a dry run or help; The reason is escaped, valid UTF-8 and cut at 200 bytes. **Rate control** (`foundation.WithRestartPolicy(RestartPolicy{...})`, code only, zero means the default, bounded: a mistake stops startup): requests are one restart that begins after `Debounce` (250 ms, trailing) of quiet but no later than `MaxDebounce` (2 s) after the first, not sooner than `MinInterval` (1 s) after the instance started, and with at most `Limit` (5, max 1000) begun per `Window` (1 min); one that is due at the limit is *held*, not dropped, until the oldest is a Window old, with one `restart held` error log; `Restart` only counts and moves a timer (no goroutine or allocation per request), logs `restarting` with the latest reason and `requests` when it begins, and a request made before the root function returned is still carried out (`process.again` waits for it; a shutdown ends the wait). **Candidate** (`process.validate`/`try`): before a due restart stops anything, the root function is run again as a candidate, a dry run beside the live instance (same options plus `WithDryRun(true)`, a `process` of its own so its `Fail`/`Shutdown`/panic can't fail or end the real run, a default registry of its own, log lines tagged `candidate=true`, the watchdog is `WithDryRunTimeout`). It passes only if it reached the end of startup (`root.completed`) with nothing failed or abandoned (`hung`); a root function that calls `Shutdown` itself fails it. A pass begins the restart; a failure logs one `restart rejected` error, with the `cause` (the first thing that went wrong in the candidate: its `Fail` error, a panic, that it asked for a shutdown, that a function did not stop, that the dry run did not finish; kept by `root.note` only on a candidate, escaped and cut at 200 bytes, text the candidate already logged), a `why` and a `hint` that sends the reader to the `candidate=true` lines for the detail (provider, field, key), and leaves the live instance alone. A request made while it runs sets its result aside once (`retried`), so a source that never goes quiet still gets a restart. `RestartPolicy.SkipValidation` turns it off, and the program's root function must honour the dry run contract (code before a skip runs twice). A shutdown aborts a running candidate and `Run` waits for it. **Every attempt counts against `Limit`** (recorded when a candidate starts, pass or not, so a flood of bad edits is at most `Limit` candidates a `Window`), and **a candidate that left a function running** (abandoned: `hung`, as for a function ignoring its context) sets `process.leaked`: the first is rejected, every later restart is refused with one `restart refused` error and nothing is tried again. **`f.Watch(trigger)`** (`watch.go`; a method, there is no `foundation.Watch`) starts a watcher as a parallel child named `watch` of `f`: it asks the trigger to watch before returning (baseline taken), then a `Restart` event is `f.Restart(reason)` and a `Shutdown` event is `f.Shutdown("shutdown requested by a watch", reason attr)` (the reason is never the log message, escaped and cut at 200 bytes); an invalid kind is dropped, and a channel that closes on its own logs one `watch ended` warning. It outlives the function that started it and is stopped in the usual reverse order (started first, stopped last; the trigger's context is cancelled at its turn). A trigger that errors, panics, returns no channel or is nil (typed nil too, even in a dry run) fails the program; it is not started in a dry run, help, a candidate, a replaced instance or after a shutdown (so a dry run doesn't find a trigger that can't start, accepted); at most 64 per instance (`maxWatchers`). **Restart on configuration change** (`configwatch.go`): a provider opts in with `config.WithRestartOnChange()` (a `config.FileOption`, so `json.File(path, config.WithRestartOnChange())`; code only, off by default) and reports what it reads as plain data through `config.Restartable.RestartSources() []config.Source{Path, Label, Dir, Extensions}` (`config` doesn't import `watch`; `config.RestartAsker` optionally says it was asked even with nothing to read). `chooseWatch` (in `instance`, after `chooseProviders`, so a dry run finds mistakes too) asks every provider in the stack, recovers a panic, and fails startup before the root function with a fixed reason (`invalid configuration options: ...`, never what the provider said) for: more than 64 sources, an empty, NUL or over 4096 byte path, a bad label (as `watch.WithLabel`), a directory without 1 to 8 extensions or an extension that is not a dot and a name of at most 16 bytes. `watchConfig` wraps the root function (before `startup` does, so modes are known and it runs before any `f.Load`) and, outside a dry run and help, logs `watching configuration` (`sources`, `names`: labels or paths) and calls `f.Watch(watch.Any(...))` with one `Files`/`Dir` per source (a `Dir` is filtered by `confdir.Match` with the source's extensions); when a provider asked but has nothing to read (an unset variable) it logs `no configuration to watch` instead. Env-sourced paths are labelled `$NAME`, so no path from the environment reaches a log. `f.Load(dst, providers...)` fails when a provider that asked to restart is not in the root's stack (`refuseUnwatched`, identity comparison), as nothing would watch it. The watcher is a parallel child, like `signals`, so a program whose root function returns keeps running until shutdown. `json`/`yaml` `File`, `FileFromEnv`, `Dir`, `DirFromEnv` implement it (a `Dir` reports `.json`, or `.yaml` and `.yml`). See `examples/config/reload` and `examples/restart` (explicit `f.Watch`). Not yet: `foundation.Watch`. State kept outside the root function (package variables, closures) is not reset, and that includes a provider the program makes and hands in (`WithConfigProviders`, `SetCommandConfig`): it is the same object for every instance and for a candidate beside the live instance, so a provider must give the same answer when asked again and be safe for concurrent use (`config.Provider` says so; `TestProvidersCanBeReused` checks env, JSON, flags and YAML). The flags provider remembers which field owns each flag (`owner`: the struct type and the Go path) and which struct read each argument (`claim.typ`), so the same struct loading again is not a second reader while a different field taking a flag is still refused.
- **Deterministic ordering**: children start FIFO, stop LIFO, cleanups (via `f.Cleanup`) run LIFO. Each cleanup runs in a goroutine of its own and is waited for, so one that panics (a failure, logged with its stack) or calls `Fail` affects only itself and the rest still run. `Parallel` twice is the same as once, `Fail(nil)` is a failure ("failure with no error"), a `SetTimeout` that is not positive means the default, and a nil provider (typed nil too) given to `Load` is skipped. All text that an outsider can influence goes through `internal/safetext.Escape` (control, format, separator characters, odd spaces and invalid UTF-8 shown escaped; `watch` keeps its own copy as it imports only the standard library). `f.Probes()` is a view per function over the instance's registry, so a duplicate probe fails the function that added it. New `f.Run` calls are ignored once shutdown has begun.
- **Per-node shutdown timeout** (default 30 s, `f.SetTimeout`, which must be called *before* `f.Parallel()`): if a node doesn't exit in its turn it is abandoned with a WARN log, its live descendants are cancelled at once, and the sequence continues. Timeouts add up across siblings, and a timeout is not a failure (exit status is unaffected). A node's timeout is for what the node does itself: its function gets it to return, and its own cleanups get it again once its children have stopped (each child under its own timeout), so slow children can't make a healthy parent look abandoned, which would fail a restart.
- A node's context is cancelled in its turn in a shutdown (the root's at once, synchronously), and otherwise when the node has finished completely: its function, its parallel children and its cleanups. It carries the parent's values but not its cancellation. A function that returns while its children carry on (the usual root function) keeps its context until then, and that is deliberate: cancelling at return would cancel the root's context while the program runs, and a cleanup sees it live unless a shutdown came first.
- **Dry run and `Skip`** (modelled on `testing.Short()`/`t.Skip`): `foundation.WithDryRun(bool)` walks the whole tree so every `f.Load` runs and checks its configuration (providers, `required`, `Validate`, `${}` expansion, and the strict check at the end), but a function that would start something calls `f.Skip(reason, attrs...)` when `f.DryRun()` is true (`Goexit` like `Fail`, but not a failure: info log `skipped`, cleanups run, a sequential parent carries on; it works outside a dry run too, e.g. for a disabled feature). `interrupt.Signals` and the HTTP server (after its `Load`, validation and certificate load, before it listens; so `health.Server` too) skip themselves. The run logs `dry run: nothing will be started`, and when the root function returns (after the strict check) stops anything still running and logs `dry run complete skipped=N`; exit status is 0, or 1 with the usual reports. A watchdog (`WithDryRunTimeout`, default 10 s, non-positive means the default) fails a dry run that doesn't finish and names the live functions in `dry run did not finish` (`running`, `hint`). It is only ever chosen by the program (typically from argv), never from the environment or configuration: a service that quietly started nothing and exited 0 would look healthy. Any new component that listens, spawns workers or otherwise starts something must skip in a dry run after it has loaded and validated its configuration; see `examples/dry-run`.

```
foundation.Run("svc", func(f *F) {
    f.Run("signals", ...)   // sequential — parent waits
    f.Run("http.server", func(f *F) {
        f.Parallel()        // parent proceeds immediately
        // ... server lifecycle
    })
})
```

### Module layout

| Module path | Go module file | Purpose |
|---|---|---|
| `go.krak3n.dev/foundation` | `go.mod` | Core framework (`foundation`, `interrupt`, `health`, `transport/http`, `config`, `watch`) |
| `go.krak3n.dev/foundation/config/yaml` | `config/yaml/go.mod` | YAML provider (the only module with a third party dependency, `go.yaml.in/yaml/v3`) |
Module sets (`core`, `yaml`) are tracked in `.release/versions.yaml` (read by `set-core-version.sh`). **Releases** (`.release/config.json`, tested by `.github/scripts/test_release_config.py`): two components, the core (tag `v0.1.0`, which excludes `config/yaml` so a parser fix isn't a core release) and `config/yaml` (tag `config/yaml/v0.1.0`, the form Go needs for a module in a subdirectory; not linked to the core); both start at `0.0.0` in the manifest, so the first release of each is `0.1.0`. **The first release published both at once, and `config/yaml/v0.1.0` requires core `v0.0.0`, which never existed, because the cascade only runs after the core is released** (the cascade then made `config/yaml` require `v0.1.0`; the tag could not be removed, so `config/yaml/go.mod` retracts it and its next release is the first usable one). A release of the yaml module that follows a core release is fine, because the cascade has by then moved its requirement; it is only the first one that has to wait. The rehearsal of the cascade (a `workflow_dispatch` from `main`) can't show what a real release does: a release checks out its tag, a detached commit, which is why `create-pull-request` is given `base: main`. 

### Key packages

**`foundation`** — the `*F` type, `Run`, `Fail`, `Shutdown`, `Parallel`, `Cleanup`, `Context`, `Log`, `Probes`, and `Load` (config loading, see below). `f.Path()` returns the hierarchical path of a function as a `[]string` (a copy), and `f.String()` joins it with `/` (the `fn` log attribute and the probe name; printing an `*F` is safe). It imports `config`, `config/env` and `config/flags` for the default providers. Layout: `foundation.go` (`F`, `Run`, the lifecycle), `stop.go` (shutdown and the stop sequence), `dryrun.go` (`DryRun`, `Skip`, startup); what an instance's functions share (options, mode, providers, probes) is one `runState` that every `F` of the tree points to (embedded, so `f.dryRun` works from any function), and what outlives an instance is the `process`. `internal/nilcheck.Is` is the one check for a nil inside an interface (a typed nil), used by `foundation` and `transport/http`; `watch` keeps a copy, as it imports only the standard library, so change both together.

**`interrupt`** — `Signals(f, opts...)` / `SignalFunc(opts...)`: a function named `signals` that starts `f.Watch(newTrigger(Shutdown, sigs...))` (SIGINT and SIGTERM by default) and, when there are any, `f.Watch(newTrigger(Restart, sigs...))` (**none by default**: SIGHUP is also what a closing terminal sends, so a restart on it is a choice), then `f.Parallel()`; the watchers are its children (`svc/signals/watch`), so a shutdown is logged as `shutdown requested by a watch` with `reason="signal: interrupt"`. `interrupt.Kind` is `watch.Kind` (alias) with `Shutdown` and `Restart` constants. Options are `interrupt.Option`/`Options` (applied in order, nil skipped; arguments are copied when the option is made): `WithSignals(kind, ...)`, `SetSignals(kind, ...)` (replaces the defaults for that kind), `WithoutSignals(kind, ...)` (by value), and helpers `WithShutdownSignals`, `WithRestartSignals`, `SetShutdownSignals`, `SetRestartSignals`; the adapter is unexported. A bad set stops startup (a failure with a fixed reason, or through the watcher): no shutdown signals at all (`signal.Notify` with no signals used to relay *every* signal, SIGURG included), SIGKILL/SIGSTOP, nil or a non-`syscall.Signal`, a signal in both kinds (SIGINT and SIGTERM are only shutdown signals by default: move them out of the shutdown set and a restart on them is allowed), or a kind that is neither; a dry run skips before that, so it doesn't find one (as for any `f.Watch`). Because it is usually started first it is stopped last, so it is still handling signals while a restart stops the rest (a signal then is a shutdown, which wins), and the shutdown watcher gives its signals back as soon as the first arrives: a second Ctrl-C gets the default action and force quits a slow shutdown (tested in a child process). The signal trigger (`trigger.go`, unexported: `watch` has no signals, and no way to name a signal as special) refuses a bad kind, none, SIGKILL/SIGSTOP and non-`syscall.Signal`s, holds at most one event like every trigger (a second restart is dropped, a shutdown replaces a waiting restart and is terminal), gives a shutdown's signals back **before** delivering, and keeps a restart's handling, and discarding, its signals for a **grace** of 10 s after it ends (`signalsGrace`, one handler per signal in `graces`, extended by each trigger that ends, so it is bounded however many come and go; held *before* the trigger gives its own back so there is no gap), because a restart stops the watch and starts another and an unwatched SIGHUP ends the process; a trigger started during the grace still gets the signal, and a shutdown gets no grace; tested in child processes, with the parent catching SIGHUP first, since exec keeps a signal that was started ignored, which would hide the default action; Go itself ignores SIGUSR1/SIGUSR2 so only SIGHUP/SIGINT/SIGTERM show it. Between two instances there is a short gap with no handler for SIGINT/SIGTERM, which gets the default action (accepted).

**`watch`** — a leaf package that imports only the standard library (tested: it knows nothing of config, of signals or of the framework) and says when something changed, so something else can restart or shut down; `f.Watch` (in `foundation`, which imports it) is its consumer. `watch.Trigger` is `Watch(ctx) (<-chan Event, error)`, returning once its baseline is taken (so a change after it returns is never missed; the consumer starts the watch before the function), with the channel closed when `ctx` is done or after a `Shutdown`. `Event{Kind, Reason}`: `Kind` is `Restart` or `Shutdown` (zero is not a kind, `Kind.Valid()` says; invalid kinds are dropped everywhere), `Reason` is for a log (at most `MaxReason` bytes, valid UTF-8; the receiver escapes it). Events are advice, never data. Triggers deliver through the exported `watch.Emitter` (`NewEmitter(release)`, `Post`, `Events`, `End`; `Manual`, `Any`, `Files`, `Dir` and `interrupt`'s signal trigger all use it, as should one written elsewhere), which holds at most one event: a second restart while one waits is dropped, a shutdown replaces a waiting restart, and **a shutdown is terminal**: delivered, channel closed, what was held released, nothing after it. Built in: `Files(paths, opts...)` and `Dir(path, opts...)` poll with **stat only** (nothing is opened or read, so a FIFO or device can't block them; the fingerprint is existence, mode, size, mtime, file identity via `os.SameFile` so a rename-over counts, and ctime where the system has it, `ctime_*.go`, since a write can't set it back); `Dir` stats the path before it opens it (a directory replaced by a FIFO is a change, not a hang), and sees every entry that doesn't start with a dot (subdirectories not entered; absent equals empty; more than `MaxDirFiles` is one stable state), narrowed by the caller with `WithExtensions` and `WithFilter` (the filter is given names only, never paths, from one bounded listing; a panic in it ends the watch, an error from the first look, never a crash), so it sees at least what any reader of the directory does, which can cost an event and never misses an edit; names in a reason are made safe to log (`shown`); the config watch (`configwatch.go`) passes `confdir.Match` as the filter; `WithLabel(label)` (`Files` with exactly one path, or `Dir`) names the thing in a reason in place of its path (`MaxLabel` 128 bytes, valid printable UTF-8, no control, format or separator characters, checked when the watch starts with an error that never repeats it); `Manual()` (fan-out to every active watch, concurrency safe, no-op after the end, releases its `context.AfterFunc` registration when the watch ends); `Any(...)` (fan-in with the same rules, a shutdown from one ends all and cancels the rest, a failed start stops the ones started, at most `MaxTriggers`). Options: `WithInterval` (default 1 s, from `MinInterval` 100 ms to `MaxInterval` 7 days, anything else is an error, not clamped) `WithExtensions` (dotted, exact, at the end of the name; `Dir` only) and `WithFilter` (`Dir` only, nil is an error). Triggers are chosen in code only. Tests run in `synctest` bubbles (fake clock, real files, times set with `Chtimes`; a bubble that can't end is the leak check) except those that need the real clock (ctime, FIFOs). Planned next, in small chunks: asset live reload (dev only).

**`health`** — `health.Server(f, opts...)`: starts an HTTP health server on `:3417` (all interfaces, because an orchestrator probes the pod address; the config of an HTTP server is embedded in the health server's own, so its settings are `--health --addr` (`-a`), `SVC_HEALTH_ADDR` and `health.addr`, and likewise the timeouts, TLS files and `--probe-path`, with `:3417` and blocking until ready set as defaults before `Load` so configuration can change them; the address comes from configuration, e.g. `SVC_HEALTH_ADDR=127.0.0.1:0` is loopback on a random port (an empty one is refused, not the default); a probe path that is one of the health endpoints is a startup error). Its own setting is `--health --verbose` (`VERBOSE`), whose help says what it discloses. Uses `f.Probes()` as the probe registry. Calls `f.Parallel()` once ready. The handler fails closed: a probe must return `StatusHealthy` with no error, so an error, an unknown status, a panic (recovered, and logged with its stack, never in the response) or a timeout is a failure. Each probe has a deadline (default 5 s, `WithProbeTimeout`) and only one run of a probe is in flight at a time (requests share it, a hung probe isn't restarted), which bounds goroutines and load under unauthenticated requests. Probes should honour their context. Responses are only the verdict: `?verbose` (probe names and error text) is ignored unless `WithVerbose()` or `VERBOSE` is set, because it discloses internals to anyone who can reach the port; instead each probe failure is logged (Warn `health probe failed`, Info `health probe recovered`) once per transition. Every response is `text/plain` with `nosniff` and `no-store`. `WithVerbose`, `WithProbeTimeout` and `WithResultsMarshaler` are `Option`s usable with both `Handler` and `Server`; `HandlerFunc` takes options too.

**`health/monitor`** — `Probe` interface, `Registry`/`Registrar` (safe for concurrent use: `Add` is all or nothing and rejects duplicate names, `Registry.Clear` empties it, `Seq` is a sorted snapshot; `Registrar` is only `Add` and `Seq`), `Mode` (liveness/readiness), `Status` (healthy/unhealthy/unknown; only healthy passes).

**`transport/http`** — `http.Server(f, handler, opts...)` / `http.ServerFunc(handler, opts...)`: full HTTP server lifecycle. Injects a `/_probe` health endpoint, registers a probe with `f.Probes()`, `block` (config) waits until the server is accepting connections before proceeding. **Options are only what configuration can't say**: `WithListener` (a `net.Listener` can't come from a provider) and `WithDefaults(func(*ServerConfig))` (the program's own defaults) are the only `ServerOption`s, and a test requires exactly these; the address, timeouts, TLS files, block and probe path are `ServerConfig` fields set by any provider. `ServerOption`s are applied in order on `DefaultServerConfig()` before `Load`, so what a program sets in code is a default and configuration wins over it (a program that must pin a value uses `ServerWithConfig`, which loads nothing); the function of `WithDefaults` also runs in help and in a dry run, so it only sets fields (a nil one is skipped, a panic is a startup failure), and its values are checked like configuration and never shown. A listener set that way counts as the address, and a typed nil one is cleared (`settleListener`, and `ServerWithConfig` too). An address from configuration beside a listener is not used (the listener wins) and `ServerWithConfig` logs one `Warn`, `a listener was given, so the configured address is not used`, with no attributes since the address is configuration; it is before the dry run skip, so a dry run says it too, and help never does. An address that configuration sets to an explicitly empty string (`SVC_HTTP_SERVER_ADDR=`) still fails as required even beside a listener, deliberately: it is an explicit input and fails closed (tested). All config fields are also settable via environment variables (see below). Safe defaults: `ReadHeaderTimeout` 10 s and `IdleTimeout` 120 s (0 turns each off, via the option or `READ_HEADER_TIMEOUT=0`); `ReadTimeout` and `WriteTimeout` are unlimited because of uploads and streaming. The probe requires a 2xx, ignores proxies and redirects, honours its context, probes a wildcard listener on loopback, and with TLS pins the exact configured certificate (the pair is loaded at startup, so a bad one fails before listening); `Ready` keeps retrying until healthy, then fails on timeout. Every setting of `ServerConfig` except the code-only `Listener` is also a flag after `--http --server` (`--addr`/`-a`, the timeouts, `--block`, `--probe-path`, `--tls-cert-file`, `--tls-key-file`), each with a `help` tag; a test requires any new field to have both, and one `config` name with no `env` or `json` tag beside it, and the values go through the same validation as variables. `DefaultServerConfig()` and `ServerWithConfig(f, cfg, handler)` let a component embed the server's settings in its own config (the health server does): it starts from the defaults, loads, and runs the server in its own function, which calls `f.Parallel` itself, with nothing loaded twice. An `Addr` with port 0 (`127.0.0.1:0`) listens on a port the system chooses, on that host. Address errors give the reason only (`listenError`), as net's own repeat the address. Configuration mistakes fail startup instead of changing what the server is: a certificate without a key (or the reverse) is an error, never plain HTTP (`Serve` too), and the log line says `tls=true/false`; there is no default address: `Addr` is `config:"addr,required"`, so a dry run and a real run report it missing like any required field (`invalid configuration`, key `SVC_HTTP_SERVER_ADDR`) and help, which reads nothing, doesn't; `WithListener` sets `Addr` from the listener (a placeholder when its address has no text) so it counts, and a nil one, typed nil too, is ignored, and `ServerWithConfig` (which loads nothing) still fails a hand built config with no address or listener, after the dry run skip; the shutdown budget (`shutdownBudget`): `ShutdownTimeout` 0 means what is left of `f.Timeout()` after `ShutdownDelay` and a margin (`min(max(timeout/10, 100ms), 5s)`), so the server closes what is left (`forced close` warning) before the framework abandons its function (which would fail a restart: a client holding a request open must not be able to do that), a time that does not fit raises the function's timeout with `SetTimeout`, a delay that leaves nothing or a negative value fails startup; `ProbePath` is validated (starts with `/`, not `/`, no spaces, braces, `?`/`#`, trailing slash or unclean segments) because it becomes a `ServeMux` pattern that could panic or shadow every GET.

**`config`** — a dependency-free leaf package holding only the `Provider` interface, `Unmarshal(path []string, dst any) error`, and `ProviderFunc`. Providers (including third party ones) implement it without importing the framework; `env` and `json` are leaves too, so imports always point at `foundation`, never from `config` back to it. The loading API is `f.Load(dst, providers...)` on `*F`, which uses `f`'s own path, so it works from any function without the "don't call via `f.Run`" caveat of the old `config.Load`. With no providers given it uses the root's, which are made once at `Run` (`chooseProviders`, `layers.go`) from four **layers** in a fixed order, lowest first: document (`config.DocumentLayer`; empty by default: no file is read unless the program names it), remote (`config.RemoteLayer`; empty, nothing implements it yet, etcd would sit here: above files, below env), environment (`config.EnvironmentLayer`; `env.New()`) and command (`config.CommandLayer`; `flags.New` when `WithArgs` was used). A provider is in a layer by implementing the marker interface (one exported method added to `Provider`), so the compiler stops a wrong placement and no option can put a file above the environment. Each layer has `With<Layer>Config(...)` (adds after what it holds, so it wins over the default: `WithDocumentConfig(yaml.File(...))` adds YAML after any other document) and `Set<Layer>Config(...)` (replaces it); options apply in the order given (recorded in `layerOps`, applied on the defaults once all options are known); none, a nil provider (a nil pointer in an interface too) or the same file twice in the document layer (cleaned absolute path; symlinks are not followed) is a startup error, as is mixing them with `WithConfigProviders`. `WithConfigProviders(...)` is the explicit whole stack with no layers and no defaults ; with none it switches loading off, and a nil provider in it (typed nil too) is a startup error naming its position, as in the layer options (`f.Load(dst, providers...)` still skips a nil one it is given). There is no `CONFIG_FILE` and no default file: `json.File(path)`/`yaml.File(path)` read the path the program gives (an empty path is an error from `Unmarshal`/`Check`, never a skipped file; `config.Pathed` is just `Path()`, for the duplicate check, which skips an empty one), and `json.FileFromEnv(name, opts...)`/`yaml.FileFromEnv` read the file named by the variable `name` that the program gives in code (read once at construction; unset or empty means no file, or an error naming the variable with `config.WithRequired()`; errors say `$NAME`, never the value; the name is checked by `internal/config/envname.Check`, shared with env aliases). The format is the program's choice, never the environment's or a file name's. Option mistakes are collected and `Run` fails (`invalid configuration options`) before the root function and without reading anything; a bad `WithStrictIgnore` is reported in the same failure (`invalid WithStrictIgnore`), so every startup mistake is shown at once. Providers live on the root `F`, not in a global. Every provider runs and every problem is reported: providers return all their problems joined with `errors.Join` (field problems are `*config.FieldError{Provider, Field, Key, Err}`), and `f.Load` logs one `invalid configuration` error per problem (control characters in `provider`, `field`, `key` and `err` escaped, so hostile names can't forge log lines) (with `provider`, `field`, `key`, `err` attributes) then fails once with `count=N`. Valid fields are still set. Then `Load` expands `${NAME}`/`${NAME:-default}`/`$$` in fields tagged `config:"expand"` (strings only; only values a provider changed, never defaults, and never twice; unset with no default is `config.ErrUndefined` with the variable as `key`; read from the process environment or `foundation.WithLookupEnv`; not combinable with a field a provider reads from a file: providers say which through `config.FileBacked` (`FileFields`), which the env provider implements for its `file` option; the parser is `decode.Expand`, the tag walkers `decode.Required`/`decode.Expandable` share `configFields`; see CONFIG.md Security for the trust model), then checks fields tagged `config:"required"` (a separate tag, so it works for every provider; zero, empty and nil count as not set, so use a pointer for an explicitly zero value; reported as `config.ErrRequired`, with a `key` naming where each describing provider would look) and, if the struct implements `config.Validator` and nothing was wrong so far, calls its `Validate`, whose errors are reported one by one too. The tag logic is `decode.Required` in `internal/config/decode`. **File options** (`config/fileoptions.go`): the options every file or directory provider takes are defined once, in `config`, so all formats mean the same by them: `config.WithRequired()` and `config.WithoutPermissionCheck()` are `config.FileOption`s (an interface with an unexported method, so only `config` makes one; `config.FileOptions` is a slice that is itself one, nil skipped), and a provider reads them with `config.ResolveFile(opts...)` into `config.FileSettings`, whose zero value is the strict one (the check on, nothing required). `json.File`, `FileFromEnv`, `Dir`, `DirFromEnv` and the yaml ones take `...config.FileOption`; the option is per provider, with no package level state, and is never read from the environment.

**Common names (the `config` tag)** — a field is named once, in the first element of its `config` tag (`config:"cert_file"`, `config:"addr,required"`), and every provider that reads names uses it: env uppercases it, files use it as the key. `config.Fields` (and `decode.CommonFields`, which env and JSON call) do the fallback, so third party providers agree; `Field.Common` says the name came from the config tag. A provider's own tag wins for that provider (`env:"PORT_NUMBER"`, `json:"portNo"`, `-` skips), and a tag of its own with only options takes the common name (`config:"password" env:",file"`; with no name from either it is an error). Flags never read it (`decode.Fields` stays exact), since a flag is its own decision. Nothing is inferred from the Go name. After the name only `required` and `expand`, which are options wherever they stand (so `config:"required"` still works) and can't be names; names within a small edit distance of them (`requried`, `Required`, `expnad`) are refused so a typo can't make a field quietly optional; a name is `[A-Za-z][A-Za-z0-9_]*`, at most 64 bytes, errors show it escaped and cut short; a mistake in the config tag is a problem for the field whatever the provider's tag says; two fields with the same name for one provider (case-insensitive) are an error on the later one (env already; JSON now too). An embedded struct is flattened only with neither a tag nor a common name. Widening: one tag means env and every file can set a field, so a field that must only come from the environment or a secret file keeps `env:"..."`, `env:"...,file"` and no `config` name (`examples/config/secrets`). The library's own configs (`http.ServerConfig`, `health.ServerConfig`) use `config`, with a test that nothing else is beside it. **Tags are checked once, by `decode.TagMistake`** (`internal/config/decode/tags.go`): a key the framework reads (`config`, `env`, `flag`, `help`, `json`, `yaml`) given twice in a tag (reflect would use the first and drop the rest, e.g. `config:"addr" config:"required"`), or a tag that can't be read to the end with one of those keys in it, is a problem for the field, from `Fields`/`CommonFields`, the required/expand walkers and help metadata, so it shows in a run and a dry run, with the key named and no value. `tagscan_test.go` fails on any repeated key in a struct tag in the repository (test files excluded).

**`config/env`** — reads env vars. Derives the prefix from the keys of the path (all providers share one rule, `config.Keys`: names are split into keys on anything that isn't an ASCII letter, digit or underscore, case preserved; new providers should call it, and `config.Fields`/`config.SetString`/`config.IsPlainString`, the public face of `internal/config/decode`, for the field and type rules), uppercased and joined with `_`. Field mapping uses the `env` struct tag, or else the common `config` name uppercased. Example: path `["svc", "http.server"]`, tag `config:"addr"` (or `env:"ADDR"`) → `SVC_HTTP_SERVER_ADDR`; the JSON provider reads `svc.http.server.addr` for the same path. `config/conformance_test.go` checks providers agree: add new providers there. Providers can implement `config.Describer` (`Describe(path, dst)` lists `FieldKey{Field, Key}` per field without reading anything; env and both JSON providers do, and `Load` uses it to name keys on missing required fields). Types (shared with the JSON provider through `internal/config/decode`, so both accept and reject the same things): `string`, `bool`, `int*` and `uint*` (base 10), `float*`, `time.Duration`, `url.URL`, anything implementing `encoding.TextUnmarshaler` (the hook for custom types), pointers to those, slices (comma separated) and maps (`k:v,k:v`) of them, nested structs (tagged), and embedded structs (untagged, flattened). **No error contains a configuration value:** `decode.invalid` turns every parse failure into a reason without the input (`not a valid integer: invalid syntax`, `not a valid URL`, `not a valid <type>` for types with their own `UnmarshalText`), keeping `strconv.ErrRange`/`ErrSyntax` reachable, so a password in the wrong field or a URL with credentials never reaches a log. A tagged field of any other type, or a tag option other than the name, `file` and `alias` (`env:"-"` skips), is an error at load time. `alias=NAME` (`env:"PORT,alias=PORT"`) also reads the unprefixed variable NAME (platforms set `PORT`, `DATABASE_URL`) when the prefixed one isn't set; the prefixed one wins and the alias is then not parsed (Debug `env alias ignored`, names only), only fields that name one read one, NAME must be capitals, digits and underscores (at most 128 bytes) and not a system or credential name (`PATH`, `HOME`, `AWS_SECRET_ACCESS_KEY`, `LD_*`, `DYLD_*`, `SSH_*`, ...), and it can't be combined with `file`, used on a struct, or shared with another field; `Describe`, required and strict mode all know about aliases. The `file` option (`env:"PASSWORD,file"`) lets a field also be set from the file named by `<NAME>_FILE` (Docker/Kubernetes secrets): both set is an error, trailing newlines are removed, the file must be a regular file of at most 1 MiB (`safefile`: no FIFOs, devices or directories; symlinks followed), and errors name the variable (`$SVC_PASSWORD_FILE`), never the path or the contents; provider tag options reach providers as `Tag.Options`/`Field.Options` through `decode.Fields` and `config.Fields`. Two fields reading the same variable is an error on the later one. An empty variable counts as unset except for a plain string. Names are matched exactly (case-sensitive). Construct the provider with `env.New(opts...)`; `env.WithMap(m)` (or `WithLookup`/`WithEnviron` for the pieces) injects the source, so tests need no `t.Setenv` and can run in parallel. Providers record the keys `f.Load` asks for, and `foundation.WithStrictConfig()` makes `Check` (the `config.Checker` interface, implemented by the env provider and both JSON providers) run when the root function returns, failing the run on variables under the root prefix, or keys in the JSON document under the root object, that nothing asked for (typos; an unknown JSON object is one problem, an unknown variable one each); load config before `f.Parallel()`, as the end of the root function is treated as the end of startup. Only the program's own providers (the root's stack) are checked: one given straight to `f.Load(dst, p)` is a narrower, deliberate use and is neither strict checked nor watched (a test pins it). `foundation.WithStrictIgnore(patterns...)` exempts keys that aren't typos (`_comment`, a neighbour's `SVC_LEGACY_*`): patterns are code only, matched against the whole reported key with `*` as the only wildcard (`internal/config/ignore`, case sensitive, linear, fuzzed against a regexp), only `ErrUnknown` problems can be ignored, a bad pattern (empty, only stars, control characters, over 256 bytes or 64 patterns) fails `Run` before the root function, and an Info summary plus per-key Debug lines keep the ignored keys visible. Options follow the same pattern as the root package: `Option` interface with a private apply method, `OptionFunc`, and `Options`.

**`config/json`** — JSON providers, which nest one object per key in the path (see above). A key that is read and appears more than once (exactly, or differing only in case) is a `config.ErrAmbiguous` error against the field, found by a token scan (`duplicates.go`) so that duplicates in keys nobody reads, such as repeated `_comment`s, are fine; entries of a map field are ambiguous only when exactly equal; trailing data after the document is an error; map entries are visited in key order so errors are deterministic. A `json` tag with no name (`json:",omitempty"`) takes the common name and without one is an error (it used to skip the field silently); two fields reading the same key, whatever the case, are an error on the later one. Files are read through `internal/config/safefile` (`ReadConfigFile`: regular files only, symlinks followed, no FIFOs or devices, at most 8 MiB). `json.File(path, opts...)` reads a file (missing files are skipped unless `config.WithRequired()` is given; an empty path is an error), `json.FileFromEnv(name, opts...)` the file a variable names (see Layers above), `json.Dir(path, opts...)`/`json.DirFromEnv(name, opts...)` a directory of them (`*DirProvider`: files ending in `.json`, in bytewise name order, later wins, no recursion, hidden files/`~`/`#x#` names ignored; a matching file that is a broken link, FIFO or unreadable, more than 256 files or 32 MiB in all, or any file refused makes the whole directory an error and nothing is read; names are selected by `internal/config/confdir.Match`/`List`, fuzzed; errors name `$NAME/file` for an env-sourced directory) and `json.Raw(data)` reads bytes; every file or directory provider refuses a file or directory that the group or others can write (`safefile.TooOpen`: `mode&0022`, sticky directories pass; checked on the opened file with `fstat`, and on the directory that holds it; Unix only, `perm_unix.go`/`perm_other.go`) unless `config.WithoutPermissionCheck()` is given, which is code only; the files return `*FileProvider`, raw `*RawProvider`.

**`config/yaml`** — a module of its own (`config/yaml/go.mod`, module set `yaml`; the core stays dependency-free, and a parser advisory can be fixed without a core release). `yaml.File(path, opts...)`, `yaml.FileFromEnv(name, opts...)` and `yaml.Dir`/`yaml.DirFromEnv` (`.yaml` and `.yml`; as for JSON, including the permission check; missing files skipped unless `config.WithRequired()`; the shared `safefile` rules: regular files, 8 MiB, symlinks followed; imported from `internal`, which is allowed across modules by import path) and `yaml.Raw(data)`, both with `Unmarshal`, `Describe` and `Check`. It uses only the public `config` API (`config.Fields` for names, `config.SetString` for scalars, `config.Annotate`, `config.Keys`) and mirrors the JSON provider (path levels, case-insensitive keys, per-struct `claimed` collision check, `ErrAmbiguous` for read keys, unknown-key `keyset`); `yaml` tag as an override, `-` skips, no name takes the `config` name. The library is used only as a node parser (`yaml.Node`), never to decode values. `parse.go` is where the safety is: one document only, anchors, aliases, merge keys, explicit tags (`TaggedStyle`) and complex keys refused anywhere, control characters and invalid UTF-8 refused, 8 MiB / depth 64 / 100,000 nodes (with a separator count that refuses clearly oversized input before parsing builds the nodes), a `recover` around the parser, and errors that are only `yaml: line N: <fixed reason>` (the library's message is never used, as it can quote the input; the line is read from it as digits only). Scalars are source text (`Node.Value`) and only an unquoted null (`isNull`) is "unset"; bools are exactly `true`/`false`; a scalar where a mapping belongs is an error (JSON ignores it). Tests: provider, hostile (canary values, bombs, limits, control characters), file (FIFO, device, symlink, 8 MiB), names (the common-name table), strict, conformance with env and JSON (it lives here, as the core can't import YAML), and `FuzzUnmarshal`. The examples are `config/yaml/example` and `config/yaml/example/dir` (a directory and `FileFromEnv`; the root module's `examples/` can't import this module); the JSON one is `examples/config/files`. The module requires the core at `v0.0.0` until the release cascade moves it, so it builds in a workspace (`make workspace`, which also `replace`s the core; `make work` needs crosslink, whose `go install` currently fails because its go.mod has `replace` directives).

**`config/flags`** — reads command line arguments, only when the program gives them with `foundation.WithArgs(os.Args[1:])` (copied; `os.Args` is never read by the framework). Fields opt in with `flag:"name,short=p"` (names `[a-z][a-z0-9-]*`, one ASCII letter for short; a field with `env:"...,file"` can't be a flag; a tagged nested struct hyphenates: `--db-host`). `--name=value`, `--name value`, bare `--bool`, `-p 8080`, `-p=8080`; no clusters, attached values, `--`, abbreviations or case folding; a value starting with `-` needs `=`. A function's flags follow its marker, its name split by `config.Keys`, lower case, `_` as `-` (`--http --server --port 8080` is `http.server`); a flag belongs to the nearest marker before it, a scope ends at the first flag it doesn't have, the root's flags come first with no marker, and a marker that could mean two functions (or is also a flag) is `ErrAmbiguous`. Every argument must be read: `Provider.Check` (run by the framework when startup ends, strict or not, never covered by `WithStrictIgnore`) reports each unread one by name or position (`argument 3`), never a value. Limits `MaxArgs` 1024, `MaxArgLength` 4096, `MaxDepth` 16, `MaxNameLength` 64. With `WithArgs` the command layer holds the flags provider by default; `SetCommandConfig` without a flags provider (or `WithConfigProviders` without one) leaves the arguments unread, which fails the run, so name `flags.New(flags.WithArgs(args))` to keep flags. The framework defines the root's own flags as an ordinary struct (`modes`: `--dry-run`, which must come first; the root can't claim the word); `--dry-run` is `WithDryRun`. `--help`/`-h` is read by the provider itself (`Provider.Help`), can be given anywhere (it doesn't end a function's scope) and is reserved in every scope: after a marker it narrows help to that function. Help (`help.go`) is a dry run that describes instead of reading: `f.Load` only calls `Describe` on the other providers (never reads, expands, checks `required` or calls `Validate`) and parses the arguments into a throwaway copy of the struct so mistakes are found as in a real run; `f.Help(text)` and the `help` tag (via `config.Annotate`, which fills `FieldKey.Provider/Help/Type`) say what things are for; the HTTP and health servers call `f.Help` with fixed text of their own (no defaults or values), on `--server` and `--health`; `--http` is only the first word of `http.server`, not a function, so it has no text; only functions with `flag` fields are listed (plus the ancestors needed); the output is printed once every function has finished (after the unread-argument check, so argument mistakes win with exit 1), to stdout or `WithHelpOutput`, escaped, with `f.Help` at most 16 KiB, tags 1 KiB and output 1 MiB (fail closed); defaults and values are never shown, and only warnings and errors are logged. See `examples/help`.

**`foundationtest`** — `LogRecorder`: a `slog.Handler` that captures log entries for test assertions. Call `recorder.Install(t)` to replace the default logger for the duration of the test. `ExitRecorder` does the same for the process exit: `Run` ends the process with status 1 after a `Fail` or panic, so any test that triggers one must call `foundationtest.NewExitRecorder().Install(t)` or the test binary will exit. It is for tests only: never import it from non-test code. Prefer `testing/synctest` for tests that depend on shutdown timeouts.

### Configuration pipeline

Config loading is explicit — call `f.Load(&cfg)` at the point of use, which applies the layers (default: env vars, then flags with `WithArgs`; files are opt in, see the layer options) or `foundation.WithConfigProviders`, or pass providers to use only those:

```go
cfg := MyConfig{Port: 8080}           // set defaults
f.Load(&cfg)                          // apply the tree's providers (defaults: env)
opts.apply(&cfg)                      // apply programmatic overrides, which win over configuration
```

`f.Load(&cfg, env.New())` applies only the providers given.

### Options pattern

All first-class components (`foundation.Run`, `health.Server`, `transport/http.Server`) use the same functional-options convention: an unexported config struct, a public `Option` interface with a private `applyXxx` method, and an `OptionFunc` adapter. Options slices also implement the interface so they can be composed.

### High-level component usage

End users of the framework typically compose the pre-built components rather than nesting raw `f.Run` calls:

```go
foundation.Run("svc", func(f *foundation.F) {
    interrupt.Signals(f)          // graceful OS signal handling
    health.Server(f)              // health/readiness HTTP server
    transport_http.Server(f, mux) // application HTTP server
})
```
